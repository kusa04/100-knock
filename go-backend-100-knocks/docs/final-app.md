# 100 問で出来上がるもの

## 最終形: マルチテナントのタスク管理 SaaS バックエンド

100 問を通して育てるコードは、最後には次の機能を持つ 1 つのバックエンドになります。Asana や Linear のような「チーム向けタスク管理サービス」の API サーバーを、フロントエンド抜きで実装するイメージです。

| 領域 | 出来上がる機能 | 主な問題 |
| ---- | -------------- | -------- |
| コア | Task の作成・更新・削除・状態遷移・サブタスク・タグ・優先度・コメント | 1〜25, 47 |
| 組織 | テナント(Workspace)/ Project / Member / Role による分離と認可 | 40〜42, 50 |
| API | REST(JSON)と gRPC の両方。カーソルページネーション、検索、部分更新、楽観ロック | 11〜17, 48, 51〜56 |
| 認証 | API キー(サービス間)と JWT(ユーザー)、鍵ローテーション | 41, 80, 84 |
| 永続化 | PostgreSQL、マイグレーション、トランザクション、Outbox、採番、バルク処理 | 30〜39, 45, 60, 61 |
| 非同期 | DB ベースのジョブキュー、再試行、デッドレター、定期実行、Outbox リレー | 68〜72 |
| 連携 | Webhook 配信(署名付き、冪等、リトライ、サーキットブレーカ)、サブスクリプション管理 | 24, 43, 44, 70, 99 |
| ファイル | CSV エクスポート / インポート(同期・非同期)、添付ファイルのオブジェクトストレージ保存 | 64〜67, 71 |
| 運用 | 構造化ログ、トレーシング、メトリクス、pprof、graceful shutdown、無停止マイグレーション | 19, 85〜88, 94, 95 |
| 品質 | race detector、モック、DB テスト、攻撃的テスト、ベンチマーク、負荷試験、lint ゲート | 21, 27, 32, 74, 83, 89〜91 |
| 開発体験 | Wire による DI、Dockerfile、compose 一発起動、OpenAPI、ADR、CLI クライアント | 57, 62, 63, 73, 97, 100 |

問題 100 の時点で `docker compose up` により「API サーバー + ワーカー + PostgreSQL + MinIO」が起動し、CLI か curl で一通りの操作ができる状態になります。

## この土台から作れるアプリ

100 問の成果物はそのまま「バックエンド API」なので、フロントや用途を足すと次のようなアプリになります。難易度順に並べています。

1. **個人 / チーム用 ToDo・かんばんアプリ**
   出来上がった REST API に薄い Web フロント(React / Next.js / SvelteKit)や CLI をかぶせるだけで成立します。かんばん表示は Status ごとの一覧 API、期限リマインドは問題 72 の定期ジョブ、Slack 通知は Webhook 配信をそのまま使えます。

2. **バグトラッカー / 問い合わせ管理(ヘルプデスク)**
   Task を「チケット」と読み替え、コメント(47)、添付ファイル(67)、担当割り当て(50)、監査ログ(82)、CSV での一括登録(65, 66)がそのまま要件になります。メール受信で起票する連携を足すと問い合わせ管理になります。

3. **採用・営業などの「案件パイプライン」管理(ミニ CRM)**
   Status をパイプラインのステージ、Project を求人や商談区分に読み替えます。集計クエリ(59)がダッシュボード、ストリーミングエクスポート(64, 92)が月次レポート出力に対応します。

4. **Webhook 中継 / イベント配信サービス**
   Outbox(45)、リレー(70)、サブスクリプション管理(99)、署名とローテーション(43, 84)を切り出すと、Stripe や GitHub の Webhook 基盤のような「イベントを受けて外部へ確実に配る」サービスになります。

5. **SaaS の共通基盤(スターターキット)**
   テナント分離、認証・認可、ジョブキュー、可観測性、CI 品質ゲートは業務ドメインに依存しません。`domain/task` を別ドメインに差し替えれば、任意の B2B SaaS の骨格として再利用できます。

## 作る場合の進め方

- 100 問終了後の追加開発は、必ず「domain → usecase → port → adapter → handler」の順で縦に切って進めてください。問題 98・99 と同じ進め方です。
- フロントエンドを付ける場合は、問題 97 で書いた OpenAPI から型を生成すると API との齟齬が減ります。
- 公開する場合は、問題 80〜84 のセキュリティ項目と問題 73 のシークレット管理を再点検してください。
